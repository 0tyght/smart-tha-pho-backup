# รุ่นทดลองหน้าปฏิบัติงานสาธารณภัยและประปา

ฉบับ 27 ตุลาคม 2569 — งาน UX/UI ที่กดทำขั้นตอนและเก็บข้อมูลในเบราว์เซอร์ได้ ยังไม่ใช่โมดูล production/backend

## เปิดใช้งาน

เข้าสู่ระบบกลางแล้วเลือกระบบตามปกติ หรือเติม `?preview=1` ที่ URL ของสองระบบเพื่อเปิดพื้นที่ตัวอย่างที่ไม่มี API และไม่มีข้อมูลจริง

`npm run dev:disaster` เปิดพอร์ต 5176 และ `npm run dev:water` เปิดพอร์ต 5177 ภายใน monorepo เดิม

## ประปา

- หน้าเริ่มคือ `apps/waterworks-management/src/presentation/WaterOperationsApp.jsx` ซึ่งประกอบผ่าน `main.jsx` (App.jsx เดิมยังเก็บไว้เป็นประวัติหน้าสาธิตเดิม ไม่ใช่ entry ที่รัน)
- ภาพรวม / น้ำจ่ายออก / จดมิเตอร์ / ตรวจและสรุปรอบ / แผนผังระบบน้ำ / รายงาน
- กรอกเลขมาตรหลักต้น–ปลายรอบ แยกเขต; กรอกเลขมิเตอร์ครัวเรือนครั้งนี้ แล้วกดบันทึก
- ส่วนต่าง = น้ำจ่ายออก − น้ำใช้รวมจากมิเตอร์ − น้ำใช้ที่อนุญาตแต่ไม่เรียกเก็บ; เปอร์เซ็นต์หารด้วยน้ำจ่ายออก
- เมื่อขาดข้อมูล ไม่สรุปส่วนต่างหรือเปอร์เซ็นต์; เลขย้อนกลับ/ค่าผิด/ส่วนต่างติดลบ/น้ำจ่ายศูนย์ต้องตรวจสอบก่อนยืนยัน
- ยืนยันแล้วล็อกรอบ สร้างรอบใหม่หลังรอบเดิมได้ เลขปลายรอบเดิมยกเป็นต้นรอบใหม่
- ส่วนต่างใช้ชี้ประเด็นตรวจสอบ ไม่ใช่หลักฐานยืนยันท่อรั่ว
- แผนผังเดิมยังอยู่ แสดงกระบวนการประกอบ ไม่ใช่ข้อมูล telemetry จริง ไม่ใช้แรงดัน/คุณภาพน้ำคำนวณส่วนต่าง
- ตัวอย่าง 400 ราย / 3 เขตเป็น fixture เท่านั้น ไม่ใช่ทะเบียนผู้ใช้น้ำของเทศบาล

## สาธารณภัย

- หน้าเริ่มคือ `apps/disaster-management/src/presentation/DisasterOperationsApp.jsx`
- คิวเหตุพร้อมรายละเอียด / แผนที่พิกัดเหตุ / บอร์ดสถานะ / ความพร้อมทีมและรถ / รายงาน
- รับเหตุ → ตรวจสอบ → มอบหมายทีมและรถ → เดินทาง → ถึงจุดเกิดเหตุ → รอตรวจผล → ปิดเหตุ
- ปฏิเสธการมอบหมายทีม/รถซ้อนงาน เก็บบันทึกทุกสถานะและรายละเอียดประกอบ
- แผนที่แสดงพิกัดเหตุที่กรอก ไม่ใช่ตำแหน่งรถ GPS; แผนที่พื้นหลังใช้ OpenStreetMap และต้องมีอินเทอร์เน็ต
- ไม่มีการรับเหตุจาก LINE, ส่งแจ้งเตือนจริง, เชื่อม OBD2 หรือส่งงานให้หน่วยฉุกเฉิน

## โครงสร้างและการทดสอบ

Domain ปกป้องกฎและสถานะ, Application ประสานงาน, Repository เก็บข้อมูล, Composition Root ฉีด dependency, React ทำหน้าที่แสดงผล

สองระบบใช้ `BrowserWorkspaceRepository` ใน web-core ร่วมกัน มี schema version และ revision เพื่อตรวจแท็บข้อมูลเก่า; JSON เสียหรือพื้นที่เต็มต้องแจ้งข้อผิดพลาด ไม่เขียนทับอย่างเงียบ ๆ

ฉบับเว็บไซต์สำรองใช้คีย์ `smart_thapho_backup_disaster_prototype_v1` และ `smart_thapho_backup_water_billing_prototype_v1` เพื่อแยกข้อมูลจากเว็บไซต์หลัก แม้ GitHub Pages ทั้งสองเว็บไซต์อยู่บน origin เดียวกัน ข้อมูลตัวอย่างของเว็บไซต์หลักจะไม่ถูกนำมารวมหรือเขียนทับ

รัน `npm test` และ `npm run build` ก่อนส่งงาน โดยชุดทดสอบสาธารณภัยถูกเพิ่มเข้า pipeline รวมแล้ว

## ข้อจำกัดก่อนเชื่อม production

ข้อมูลใช้ localStorage ของ origin/เบราว์เซอร์นี้ ไม่ใช่ MySQL ไม่แชร์ข้ามคนหรือเครื่อง และอาจหายเมื่อเคลียร์ข้อมูลเว็บ ห้ามใช้เก็บข้อมูลจริงหรือเป็นช่องทางตอบสนองเหตุฉุกเฉิน

ก่อนเปิดงานจริงต้องเพิ่ม API และ MariaDB repositories, สิทธิ์ตามบทบาท/พื้นที่, audit log ฝั่ง server, transaction/locking ทรัพยากร, การสำรองและกู้คืน และการทดสอบอุปกรณ์/LINE จริง งานรอบนี้ไม่ได้แก้ schema ฐานข้อมูลหรือ Webhook ระบบหลัก
